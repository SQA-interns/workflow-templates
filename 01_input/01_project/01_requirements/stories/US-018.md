# US-018 Merge two Contacts

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Editor, I want to merge a pair of Possible duplicates into one Primary contact, choosing which value to keep for each Field, so that the Group has one correct Contact instead of two.

## Purpose

The customer expects merging of duplicate contacts (Q-09 F7) without losing information or History (Q-26).

## Definitions

| Term | Meaning |
|---|---|
| Merge screen | The two Contacts side by side, with a choice of Primary contact and, per Field, which value to keep. |
| Other contact | The Contact of the pair that is not the Primary contact. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-018-01 | When the Owner or an Editor opens "Merge" for two active Contacts of the Group, the system shall show the Merge screen with the first Contact as Primary contact and, per Field, the Primary contact's value preselected if non-blank, else the Other contact's value. [ASSUMPTION] preselection not given. | Q-26, Q-18 (OPEN — needs customer) |
| R-018-02 | When the User confirms the Merge, the system shall give the Primary contact the chosen Field values, all Tags of both Contacts, and all Attributes of both Contacts, and create one Version of kind `merged` on it. | Q-26, BR-05 |
| R-018-03 | If both Contacts have an Attribute with the same key and different values, then the system shall require the User to choose one value before the Merge can be confirmed. [ASSUMPTION] not given. | Q-26 |
| R-018-04 | When the Merge is confirmed, the system shall set the Other contact to `merged` with `mergedInto` = the Primary contact, create a Version of kind `merged` on it, keep both Histories, and write an Audit entry. | Q-26, BR-10 |
| R-018-05 | The system shall show on the Primary contact "Merged from <name of Other contact>" with a link to the Other contact's History. [ASSUMPTION] not given. | Q-26 |
| R-018-06 | If the combined Attributes exceed 50, then the system shall reject the Merge with "Together these Contacts have more than 50 Attributes; remove some first." and change nothing. | Q-27 |
| R-018-07 | If either Contact is not active, belongs to another Group, or carries a stale Version number, then the system shall reject the Merge and change nothing (BR-06 for a stale Version). | Q-26, BR-06 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-018-01 | Same Attribute key, same value | Kept once, no choice asked | R-018-03 |
| EX-018-02 | Combined Attributes 50 / 51 | Merged / rejected | R-018-06 |
| EX-018-03 | One Contact moved to the recycle bin meanwhile | Rejected; nothing changes | R-018-07 |
| EX-018-04 | One Contact edited by someone else meanwhile | Rejected as BR-06 | R-018-07 |
| EX-018-05 | Merging a Contact with itself | HTTP 400; nothing changes | R-018-07 |
| EX-018-06 | Marko cancels | Nothing changes | BR-07 |
| EX-018-07 | Same Tag on both | Kept once | R-018-02 |

## Out of scope

Merging three or more Contacts at once; merging across Groups; Undo merge (US-019).
