# US-012 Move a Contact to the recycle bin and restore it

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Editor, I want to delete a Contact into a recycle bin from which it can be restored for 30 days, so that a Contact deleted by mistake is not lost.

## Purpose

Deletion is irreversible for the customer's data; the proposed answer is a recycle bin with a 30-day restore period (Q-22, OPEN — needs customer).

## Definitions

| Term | Meaning |
|---|---|
| Recycle bin screen | The list of a Group's Contacts in the recycle bin, with name, deleted by, deleted at, and removal date. |
| Removal date | `deletedAt` + recycle bin period (project-wide facts). |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-012-01 | When the Owner or an Editor confirms "Move to recycle bin" for an active Contact, the system shall set it to `inRecycleBin` with `deletedAt` = now and create a Version of kind `movedToRecycleBin`. | Q-22 (OPEN — needs customer), BR-05 |
| R-012-02 | The system shall show the recycle bin screen to the Owner and Editors only, sorted by `deletedAt` newest first. [ASSUMPTION] Viewer access not given. | Q-22 |
| R-012-03 | When the Owner or an Editor restores a Contact from the recycle bin before its removal date, the system shall set it to `active` with all its Fields, Attributes, Tags and History, and create a Version of kind `restoredFromRecycleBin`. | Q-22, BR-05 |
| R-012-04 | If a Contact is restored at or after its removal date, then the system shall reject it with "This Contact can no longer be restored." and change nothing. | Q-22 |
| R-012-05 | The system shall run the removal of BR-08 at least once per hour. [ASSUMPTION] interval not given. | Q-22 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-012-01 | "Janez Novak" is active at Version 3 | Marko confirms "Move to recycle bin" on 05.03.2026 at 11:00 Europe/Ljubljana | "Janez Novak" is not in the Contact list; the recycle bin shows it with "deleted by Marko Kranjc, 05.03.2026 11:00, removal 04.04.2026 12:00"; Version 4 is `movedToRecycleBin` | R-012-01, BR-09 |
| AC-012-02 | as AC-012-01 | Ana restores it on 20.03.2026 | it is in the Contact list again with its Tags and Attributes; Version 5 is `restoredFromRecycleBin` | R-012-03 |
| AC-012-03 | "Janez Novak" was moved to the recycle bin 30 days and 1 hour ago | Ana opens the recycle bin | it is not listed and `GET` on the Contact returns HTTP 404 | BR-08, R-012-05 |
| AC-012-04 | Petra is Viewer | she moves a Contact to the recycle bin through the API | HTTP 403; nothing changes | BR-03 |
| AC-012-05 | Petra is Viewer | she opens the recycle bin through the API | HTTP 403 | R-012-02 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-012-01 | Restore 1 minute before the removal date | Restored | R-012-03 |
| EX-012-02 | Restore exactly at the removal date, before the removal job ran | "This Contact can no longer be restored." | R-012-04 |
| EX-012-03 | Marko cancels the confirmation | Nothing changes | R-012-01, BR-07 |
| EX-012-04 | Move to recycle bin with a stale Version number | Rejected as BR-06 | BR-06 |
| EX-012-05 | Contact in the recycle bin searched for | Not found in the Contact list, filters or Export | BR-09 |
| EX-012-06 | Moving a Contact that is already in the recycle bin | HTTP 409; nothing changes | R-012-01 |

## Out of scope

Moving several Checked contacts at once; a different period per Group; permanent delete (US-013).
