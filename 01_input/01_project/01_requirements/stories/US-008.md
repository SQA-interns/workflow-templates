# US-008 Keep Attributes on a Contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Editor, I want to add, change and remove free key–value Attributes on a Contact, so that I can keep information the fixed Fields do not cover, such as `kompetenca=spletnoProgramiranje`.

## Purpose

The customer wants contacts defined freely as key–value pairs in addition to the predefined data (Q-09 F3).

## Definitions

None.

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-008-01 | When the Owner or an Editor saves a Contact with added, changed or removed Attributes, the system shall store them in the same save as the Fields and list each as the changed item `attribute:<key>` in that one Version. | Q-27, BR-05 |
| R-008-02 | If an Attribute key is blank after trimming or longer than 50 characters, then the system shall reject the save with "A key must have 1 to 50 characters." and store nothing. | Q-27 |
| R-008-03 | If an Attribute value is longer than 500 characters, then the system shall reject the save with "A value may have at most 500 characters." and store nothing. [ASSUMPTION] an empty value is allowed. | Q-27 |
| R-008-04 | If two Attributes of one Contact have the same key, compared case-insensitively after trimming, then the system shall reject the save with "The key <key> is used twice." and store nothing. | Q-27, BR-11 |
| R-008-05 | If a save would leave a Contact with more than 50 Attributes, then the system shall reject it with "A Contact may have at most 50 Attributes." and store nothing. | Q-27 |
| R-008-06 | The system shall show a Contact's Attributes sorted by key A–Z, with the key spelled as entered. [ASSUMPTION] order and spelling not given. | — |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-008-01 | "Janez Novak" at Version 1 without Attributes | Marko adds `kompetenca` = `spletnoProgramiranje` and saves | the Contact shows the Attribute; Version 2 lists "kompetenca: (empty) → spletnoProgramiranje" | R-008-01 |
| AC-008-02 | "Janez Novak" has `kompetenca=spletnoProgramiranje` | Marko changes the value to `mobilnoProgramiranje` and removes nothing else | Version 3 lists "kompetenca: spletnoProgramiranje → mobilnoProgramiranje" | R-008-01 |
| AC-008-03 | as AC-008-02 | Marko adds a second Attribute `Kompetenca` = `java` | "The key Kompetenca is used twice." and nothing is stored | R-008-04 |
| AC-008-04 | as AC-008-02 | Marko removes `kompetenca` | Version lists "kompetenca: mobilnoProgramiranje → (removed)" | R-008-01 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-008-01 | Key of 50 / 51 characters | Saved / rejected | R-008-02 |
| EX-008-02 | Key "   " | Rejected | R-008-02 |
| EX-008-03 | Value of 500 / 501 characters | Saved / rejected | R-008-03 |
| EX-008-04 | Empty value | Saved | R-008-03 |
| EX-008-05 | 50th Attribute added / 51st added | Saved / rejected | R-008-05 |
| EX-008-06 | Field and Attribute changed in one save | One Version with both items | R-008-01 |
| EX-008-07 | Save with a stale Version number | Rejected as BR-06 | BR-06 |

## Out of scope

Typed values (numbers, dates); a Group-wide list of allowed keys; key suggestions; filtering by Attribute (US-015).
