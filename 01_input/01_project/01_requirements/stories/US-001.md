# US-001 Sign up and sign in

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As a User, I want to sign up and sign in with my e-mail and password or my Google account, so that only I can reach the Groups I belong to.

## Purpose

Contacts are personal data of third parties; without sign-in, anybody could read them. The customer requires authentication through Firebase and a secured REST API (Q-11).

## Definitions

| Term | Meaning |
|---|---|
| ID token | The signed token Firebase Authentication issues after sign-in; the browser sends it with every API request. |
| Sign-in screen | The screen with "Sign in with e-mail", "Sign in with Google" and a link to "Create an account". |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-001-01 | The system shall let a person create an account and sign in with an e-mail address and password, or with a Google account, through Firebase Authentication. | Q-11, Q-34 (OPEN — needs customer) |
| R-001-02 | When the backend receives a request, the system shall accept it only if it carries an ID token whose signature, Firebase project and expiry are valid. | Q-11, Q-34 |
| R-001-03 | If a request carries no ID token, or an ID token that is invalid, expired or issued for another Firebase project, then the system shall respond HTTP 401 and return no data. | Q-11, Q-34 |
| R-001-04 | When a User with a valid ID token calls the backend for the first time, the system shall create the User with the e-mail and display name of the token and the language `sl`. | Q-29 |
| R-001-05 | If the e-mail of a User who signed up with e-mail and password is not verified, then the system shall show "Confirm your e-mail address: we sent you a link." and the backend shall reject every other request with HTTP 403. [ASSUMPTION] e-mail verification not stated; required so that Invitations bound to an e-mail (US-004) cannot be taken over. | — |
| R-001-06 | When a User signs out, the system shall discard the ID token in the browser and show the sign-in screen. | Q-11 |
| R-001-07 | When a signed-in User is a Member of no Group, the system shall show "You have no Groups yet." with the action "Create a Group". | Q-03 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-001-01 | no account exists for `ana.kovac@example.si` | she creates an account with `ana.kovac@example.si` and password `Kontakti#2026`, confirms her e-mail and signs in | she sees "You have no Groups yet." with "Create a Group"; `GET /api/v1/me` returns e-mail `ana.kovac@example.si` and language `sl` | R-001-01, R-001-04, R-001-07 |
| AC-001-02 | a Google account `marko.kranjc@gmail.com` | he chooses "Sign in with Google" and completes it | he is signed in and `GET /api/v1/me` returns e-mail `marko.kranjc@gmail.com` | R-001-01, R-001-04 |
| AC-001-03 | any Group exists | a client calls `GET /api/v1/groups` without an ID token | the response is HTTP 401 and contains no Group data | R-001-03 |
| AC-001-04 | Ana's ID token expired | a client calls `GET /api/v1/groups` with it | the response is HTTP 401 and contains no Group data | R-001-03 |
| AC-001-05 | Ana created an account but has not confirmed her e-mail | she signs in | she sees "Confirm your e-mail address: we sent you a link."; `GET /api/v1/groups` returns HTTP 403 | R-001-05 |
| AC-001-06 | Ana is signed in | she chooses "Sign out" | the sign-in screen is shown and a request with no token returns HTTP 401 | R-001-06 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-001-01 | Wrong password for an existing e-mail | "Wrong e-mail or password." (no hint which one is wrong); not signed in | R-001-01 |
| EX-001-02 | ID token signed by another Firebase project | HTTP 401, no data | R-001-03 |
| EX-001-03 | Ana signs in a second time | No second User is created; the same User id is returned | R-001-04 |
| EX-001-04 | Token with a wrong signature (one character changed) | HTTP 401, no data | R-001-03 |
| EX-001-05 | Account creation with an e-mail that already has an account | "An account with this e-mail already exists." ; no second account | R-001-01 |

## Out of scope

Password rules other than the Firebase defaults; multi-factor authentication; other sign-in providers; changing the e-mail address; an administrator UI for accounts (the Operator uses the Firebase console). Choosing the language is US-020, deleting the account is US-021.
