# ADR-05: Configuration of variable data

- Status: accepted · Date: 2026-11-16 · Session: S3 /plan
- Drivers: ES-01, ES-02, environments.md (Configuration), Q-39 (same images on staging and production)

## Context
Settings differ per environment (environments.md). The frontend needs the Firebase web settings, but the same image must run on staging and production, so they cannot be baked in at build time.

## Options
1. Backend: Spring properties from environment variables. Frontend: `/config.json` written by the nginx container at start from environment variables; the app fetches it before it renders.
2. Frontend values as Vite build-time variables (one image per environment).

## Decision
Option 1.
- Backend `application.yml` maps `DB_URL`, `DB_USER`, `DB_PASSWORD` (no default), `FIREBASE_PROJECT_ID`, `FIREBASE_AUTH_EMULATOR_HOST`, `FIREBASE_SERVICE_ACCOUNT_FILE`, `APP_PUBLIC_URL`, `RATE_LIMIT_PER_MINUTE`, `LOG_LEVEL`; defaults only where environments.md allows them (test/local values in the `local` profile).
- Frontend `config.json` (contract `docs/02_contracts/runtime-config.schema.json`): `firebaseApiKey`, `firebaseAuthDomain`, `firebaseProjectId`, `authEmulatorUrl` (local only). Generated by `envsubst` from `config.json.template` at container start; Vite dev server serves `public/config.json` with local values.

## Consequences
- One image per component for every environment.
- A missing staging value fails at start (backend) or shows the error state (frontend), never silently uses a local default.
